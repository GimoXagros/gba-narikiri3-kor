# 인스펙트 아이 속성 기호

2026-09-09, v1.1a-dev27. 인스펙트 아이에 남은 여덟 한자 그림을 같은 한 칸 한글로 교체했다. 전체 번역 요청에 따른 개발판 표시 선택이다. 별도로 제시한 기호 표기 선호 질문에는 아직 답이 없으며, 이를 사용자의 확정 답변으로 기록하지 않는다.

순서는 실제 원본 글자 픽셀과 `168C8`/`168F0`/`16934`의 선택 결과로 확인했다. ID 0의 元은 무속성이 아니다. 무속성 ID 8의 원래 빈 출력은 그대로다. 물과 빛을 뒤바꾸지 않는다.

## 변경 경계

원래 `7C1938`의 byte 80..87 조회는 `D882EC` 템플릿을 거쳐 8bpp 글꼴의 BB..C2 타일을 선택한다. affine 자원 표 `1448E4`의 86개 레코드 중 글꼴 282의 소유자는 `(440,282,283,284)` 한 항목이다. 은행 포인터는 `D4524C + 4 + 282×4 = D456B8`이며, 원본 글꼴은 `D86384`에 있다.

240타일 글꼴을 복사하고 그중 8타일만 달무리 픽셀로 교체해 `1111000..1114C7C`에 저장한다. 원본과 같은 BIOS type-30 형식, 해제 크기 15360바이트, VRAM 목적지 `06008000`이다. 은행 포인터 한 개만 복사본으로 바꾼다. 원래 압축 자원 7972바이트, 나머지 은행 포인터, 팔레트, 맵, 속성 ID, 내성 수치와 판정 코드, dev26 한글 출력 코드는 보존한다. 새 영구 RAM이나 추가 실행 코드는 없다.

## 검증

- 정확한 ROM SHA-256: `b7bf4cfea2dd2b535e33933dd1cdfa18d38f10e7cdea14a8cae6f19f45bf733f`. 누적 빌드의 전체 분리 CPU 검사 통과.
- 원래 `51F68` 자원 선택, `3444` 은행 조회, `33F4` 해제 분기, `51E10` 맵 초기화를 기존/수정 글꼴에서 각 두 번 실행했다. BIOS RLE와 팔레트 CpuSet만 정확한 입력·출력 경계로 모형화했다. 전체 글꼴 픽셀, 팔레트, 주변 VRAM, 맵 256바이트와 인접 64바이트, 크기·프레임 메타데이터 보존을 확인했다. 별도 인스펙트 아이 280사례도 통과했다.
- mGBA와 VBA Next 새 프로세스에 정상 중단 저장 `73d7aa6ca8e0d6b064f5f0edcd1597033dc61687c585478da4da28c40687165d`을 읽고 정상 컨트롤러 기록을 재생했다. frame 6467에서 직접 선택한 기술 창의 `그린 로퍼`, HP 505/580, 세 한글 항목 및 `원암광뇌지수풍화`를 양쪽에서 관찰했다.
- 같은 코어의 dev26과 비교하면 VRAM 98304바이트 중 기호 8타일 안의 215바이트만 다르다. 실제 적을 포함하는 `02010000..02015000`의 20480바이트는 동일하다. 공격 무속성과 내성 없음은 계속 빈칸이다. RAM 변경과 상태 파일 가져오기는 0회다.
- 첫 관찰 비교 스크립트는 이전 덤프 시작 주소를 다르게 읽고 적 ID를 16비트로 읽어 두 번 실패했다. 기존 입력 기록과 원래 8비트 조회를 대조해 관찰 도구를 정정했다. 게임/ROM 변경으로 집계하지 않는다. 기록은 `output/v1.1a-dev27-inspection-*/symbol-observation.json`과 입력 로그에 남긴다.

이 결과는 정보창 한 자원에 대한 검증이다. 다른 화면의 속성 그림, 매직 렌즈 경로, 전체 게임 진행은 별도 남은 작업이다. 전체 번역률이나 무오류 판정으로 사용하지 않는다.
