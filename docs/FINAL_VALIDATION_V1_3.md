# v1.3 후보 검증 요약

상태: **v1.3 정식 릴리스용 검증 기록**. 사용자 종합 회신과 제한된 기술 근거를 구분하며, 실제 발행·최종 감사 상태는 릴리스 manifest와 GitHub Release를 따른다.

## 최종 사용자 승인과 공개 범위

2026-10-11 사용자는 비공개 검수05 이후 추가 문제 없음과 GitHub 업데이트를 승인했다. 대상은 직전 제공한 C6 ROM16MiB/SHA `d1d27b49dfeb6bbacb77b2112664efbb679f7f30a89f2cd17a1037d64fef1c4b`와 대화 문맥으로 연결하며 사용자 해시 재측정으로 기록하지 않는다. 최소 사용자 검수 대기는 이 종합 회신으로 해제한다. 기기·로더·개별 항목 결과는 UNKNOWN/NOT_RESTATED이고 에이전트 실기 실행은 NOT_RUN이다. [사용자 검수 기록](https://github.com/GimoXagros/gba-narikiri3-kor/blob/v1.3/docs/HARDWARE_ACCEPTANCE_V1_3.md)에 근거와 한계를 분리했다.

C6 독립 표적 검토는89장 중 strict87통과/2실패, bounded89통과다. 두 strict 실패는 턴종료 뒤 index0의32바이트와 index2의27바이트 이전 타일 잔류로 직접 귀속했다. PNG/OAM/PAL/CHAR는 같고 affine을 포함한 활성 OAM의 전체 텍스처 범위와 1D·2D 두 배치 모두 해당 잔류 주소의 교집합은0이다. 원시 실패를 전체 영상 통과로 바꾸지 않는다. 시스템 비활성 버튼의 자연 경로는 NOT_RUN이며 기존 필드 비활성·클레릭 두 특기 제목 회귀와 구분한다.

최종 소스의 문서·패키징 메타데이터만 갱신하며 ROM/BPS는 검수 C6와 byte-identical이어야 한다. 깨끗한 체크아웃의 재현, 명시적 공개 파일·635개 기존 소스 및 새 문서의 자동 소스 아카이브, 실제 동봉 적용기 검사와 최종 감사 판정은 외부 manifest에 정확한 커밋·파일 해시로 연결한다. 공개 자산은 BPS·사용자 ZIP·외부manifest·SHA256SUMS 네 개이며 ROM/SAV/BIOS/전체 대사집/별도 폰트 바이너리·개인 경로는 넣지 않는다.

실제 최종 감사·발행 상태는 릴리스 manifest와 GitHub Release를 따른다. 아래 실기·발행 대기 문구는 이전 후보/검수 시점의 역사 기록이며 이번 사용자 종합 회신으로 소급 수정하지 않는다. 과거 첫 저장17,767±3 실패, 초기 프레임·전투3,866프레임 차이, C5의 애니메이션 위상 예외와 C6의59바이트 비표시 잔류는 서로 다른 근거로 유지한다. 전편 무오류·모든 기기 호환·모든 과거 시험을 최신 후보에서 재실행했다는 주장은 없다.

## C6 검수 시점의 후보와 시스템 메뉴 가독성

현재 C6 시스템 메뉴 후보는16,777,216 bytes, SHA-256 `d1d27b49dfeb6bbacb77b2112664efbb679f7f30a89f2cd17a1037d64fef1c4b`이며 누적 JP BPS는525,693 bytes, SHA-256 `772fdb97a075c79a9f2e11202043ce0e0c20305597788fe94256a3280f85c55f`이다. C5에서 시스템 자원0·2·3·4·5·6·7의7개 스트림과 bank4/5 두 참조값만 추가 변경한다. 이전 C5의 필드8개와 특기45·46·48 압축 bytes는 동일하다. 일본판 금색판·장식과 흰 획을 유지하면서 같은 갈색 국소 윤곽을 적용한다.

적목록4의313바이트 LZ는 기존 후퇴5 소유345바이트 슬롯 `E737B8..E73911`에, 후퇴5의272바이트 LZ는 기존 적목록4 소유282바이트 슬롯 `E735F8..E73712`에 저장한다. 28항목 bank 위치·index·실제 컴포넌트별 위치표와 소비 코드는 유지하고 두 pointer값만 교환한다. 은퇴 suffix의 목록 프레임 `E73714..E73738` 36바이트와 새 스트림 뒤의 이전 bytes를 그대로 보존한다. 불변 OPT16에 대한 최종46개 쓰기 계획은 중복이 없고 C5→C6 단계와 byte-identical이어야 한다. C5와1,975바이트, OPT16과6,248바이트 다르며 모든 차이는 명시 범위 안이다.

정확 C6의19,851프레임 첫 저장과 별도 프로세스 콜드 로드·메뉴·아이템 설명은 제한된 PC 확인을 통과했다.17,759±0과 전체 SAV가 C5와 같다. 원래17,767±3 실패는 보존한다. 새7개 실제 선택·취소·재진입과 깨끗한 소스 A/B 재빌드·실제 패키지 검사는 별도 근거에 연결한다. 기존 광범위 시험의 전편 재실행·모든 기기 호환을 주장하지 않는다. 새 후보 실기와 최종 감사 GO는 아직 없다.

총영주 저택 합성 챕터11의 등장 인물 안내는 해롤드로 정정한다. 원본 게임 이벤트·대사 변경은 없고 사용자가 해당 장면을 정상이라고 한 회신만 기록한다. 사진의 기기와 정확 후보는 확인되지 않았으므로 C6 실기 PASS 근거가 아니다. 기존 비공개03/04와 이전 소스·관측 기록은 보존하고 신규05 검수 묶음을 만든다.

## 이전 C5 메뉴 가독성 기록

메뉴 가독성 후보 C5의 RC16은16,777,216 bytes, SHA-256 `9ce7e5f41ac9d40128276dae31bde33e423eb60bff3cc2a4559395786f9d26cb`이다. 누적 BPS는525,415 bytes, SHA-256 `2365d6d053aaa2686e840d75c064651c99299dc607ecf335aff51f55ed9c7051`이다. JP·기존1.1 IPS·추적 소스만 입력으로 사용하는 별도 깨끗한 체크아웃 두 곳에서 ROM과 BPS가 같았다. 완성 ROM은 생산 입력이 아니다.

C4 이후 필드1·8~14 및 정보45·46·48의 11개 그림 스트림만2,258바이트 달라졌다. 불변 OPT16 이후 최종37개 쓰기 범위 안에서4,529바이트가 다르며, 쓰기 계획이 서로 겹치지 않는지 검사한다. 필드1의331바이트 새 LZ는 원래 OPT16의 실제360바이트 스트림 안에 있다. C4의 재압축 소비 길이330바이트보다1바이트 길다는 사실을 원래 소유 길이와 구분한다. 다른 스트림은 자신의 실제 소비 길이를 넘지 않는다.

필드8개 버튼의 흰색 획·안쪽 공간은 같은 마스크를 유지한다. 금색판·리벳·테두리 등 글자 영역 밖 픽셀과 실제 위치표·팔레트·메뉴 코드·버튼 크기를 보존한다. 일본판 자체는 금색판 위의 흰 글씨이며 새 갈색 윤곽은 한글 가독성 보완이다. 특기 설정/사용은 기존 한글 획을 흰색으로 채우고 일본판의 남색 테두리 계열을 사용한다. 실제 버튼 선택8상태와 두 특기 제목 전환을 일반 조작으로 확인했다. 검수용 중단 및 합성 저장을 정상 진행·실기 근거로 승격하지 않는다.

정확 C5의 첫 저장19,851프레임 입력은17,759±0이며 전체 SAV가 C4와 같았다. 별도 실행의 콜드 로드·메뉴·아이템 설명도 직접 확인했다. 원래17,767±3 실패와 이전 전체 영상 비교 한계는 보존한다. 기존 대사·성능·동적 명찰4바이트·저장 코드는 바뀌지 않았다. 기존 광범위 검증은 변경 밖의 동일성으로 연결하며 C5에서 모두 재실행했다고 주장하지 않는다. 신규 후보 실기·최종 표적 감사 GO는 별도 대기다.

## 이전 C4 후보의 재현·검증 기록

이하 C4 기록은 이전 후보에 대한 근거이며 C5 전편 재실행 결과가 아니다.

RC16은 16,777,216 bytes, SHA-256 `54a138aea155d38d6730a36eeb7c480034b0ad8e9ab2d339865f2961af6480a0`이다. 누적 BPS는 525,189 bytes, SHA-256 `e0f888d7cfd1ab82b6c9c390838a5fcd2acf25a4064a13e2644445edd62edcd1`이다. 원본 일본판·개발용 1.1 IPS·생산 소스에서 기존 OPT16/OPT32 체크포인트를 정확히 재현한 뒤 후보를 생성했다. 최초 통합 이후 동적 명찰 접두부를 추가 교정한 소스의 별도 clean checkout G/H도 ROM·BPS가 같았다. 이전 C2 후보와의 차이는 `0x1BE19C..0x1BE1A0`의4바이트뿐이며 다른 모든 bytes는 두 크기에서 같다. 최종 문서·관측 프로필 커밋의 재현과 자산은 별도 manifest에 연결한다.

27개 보호된 쓰기 범위 안에서만 OPT16과 2,547바이트가 다르다. 변경된 그림은 원래 소비 스트림의 실제 길이와 명시된 소유 공간으로 연결했다. 수정 구간 밖 전체 바이트, 기존 메뉴 성능 코드와 지정한 공유 자원은 보존했다. 구현자의 생성 검사와 독립 포인터·수명·자연 화면 검사는 별도 근거이다.

## 한정된 PC 확인

아래 성능·전체 전투·공유 메뉴 비교의 최초 exact 대상은 이전 C2 후보이며 원 보고서를 보존한다. 새 후보는 명찰 접두부4바이트만 다르다는 전체 ROM 대조와 원 소비자 참조/복사 범위 근거로 영향 없는 증거를 결합한다. 새 첫 저장/콜드 로드는 새 후보 해시에 묶인 추가 검증을 완료했다. 새 명찰은 양크기 실제 accessor/글꼴 CPU와 chapter17의 실제 화면으로 추가 확인했다. speaker50의 자연 대화 호출은 재실행하지 않았으며 actual accessor/renderer 검증과 구분한다. 새 후보에서 기존 모든 시나리오를 재실행했다고 주장하지 않는다.

- 고정 RC16/OPT16 메뉴 시나리오에서 아이템 6,136개와 도감 6,264개 표본의 창·선택 ID·문자 영역이 같았다. 전체 게임 속도나 일본판과의 전체 동등성 주장이 아니다.
- 정확 후보·mGBA core·고정 입력 trace의 첫 저장 관측 두 회는 각각17,759였고 체크섬과 시간·체크섬을 제외한 저장 내용이 기준과 같았다. 이 조합에만 허용 오차0의 관측 계약을 추가했다. **기존17,767±3 검사의 FAIL은 그대로 보존한다.** 원래 논리 타이머 코드는 바뀌지 않았고, 독립 이전 비교에서 렌더링 중 완료된 논리 업데이트 수 차이가 관측됐다. 실기 시간 동등성은 주장하지 않는다.
- 정확 후보의 재저장·콜드 재로드·마을 상담 경로는 OPT16과 관측 영상 및 저장 결과가 같았다. 전투40,527프레임에서 달랐던1,230개 모두 독립 검토가 실제 바뀐 자원 bytes와 OAM의4bpp 원천 픽셀에 정확히 귀속했다. town65/80 쌍120프레임, town67/82 쌍290프레임, field1 820프레임이며 승인 자원 원천 밖의 차이는0이다. BG VRAM·OAM·팔레트·텍스트 버퍼·주 저장 본문·41캐릭터 구조는 같았다. 이는 관측 경로의 승인 그림 차이에 대한 판정이며 전체 영상 동일성 또는 전체 게임 검증은 아니다.
- 별도 PRE16→OPT16의 과거3,866프레임 차이와 strict 비교 FAIL은 유지한다. 명찰 과도 표시·wipe 경계 등 시각 분류와 미확정 개별 인과를 구분한다. 새 후보 전투의1,230개 차이와 합산하거나 같은 모집단으로 설명하지 않는다.
- RC16/FIX32의 네 고정 경로는 첫 영상 프레임만 달랐다. 초기 덤프에서 RC16은 forced blank(`DISPCNT 0x0483`), FIX32는 active(`0x0403`)였고 관측 frame2~10은 같았다. 전체 raw strict 비교의 첫 프레임 FAIL을 지우지 않으며 이 경로 밖으로 예외를 확대하지 않는다.
- 합성 해금 저장의 조작만으로 편성→캐릭터 목록→L/R→취소 경로를 확인했다. 비교 화면13개 중 안내가 바뀐09/10만 `[192,2,222,10]` 영역이 달랐고41캐릭터 값은 유지됐다. 전원이레벨99인 합성 저장이라 정렬 순서가 같았으며, 서로 다른 레벨의 실제 CPU 정렬 검사는 별도 근거이다. 정상 진행 또는 실기 검증이 아니다.
- 같은 합성 저장에서 정보 메뉴45개 지정 화면을 OPT16과 비교했다. 3개 화면의 공유52 글자70픽셀만 달랐고 모든 화면의 OAM·팔레트·41캐릭터 구조는 같았다. 앨범·도감·상태 세부 정보, 페이지 이동·취소, 카드·재료·레시피·아이템/장비·기술·편성의 지정 화면 범위이며 전체 영상 비교는 아니다. 필드 의상 선택의 group7은 독립 검토가 실제52/53 자원과 VRAM을 대조했다.
