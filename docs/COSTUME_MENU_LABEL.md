# 의상 변경 메뉴명 원문 대조

2026-09-12. 사용자 화면에 표시된 ‘변장’을 일본판의 같은 메뉴와 비교했다. 원문은 **きがえ（着替え）**, 즉 옷을 갈아입는다는 뜻이다. 설명도 나리키리 의상을 변경한다고 안내하며 한국어판 확인 문구도 이미 ‘갈아입을까요?’였다. 이 기능에는 **‘갈아입기’**가 원문과 사용 목적에 더 맞아 v1.1a dev34에서 수정했다.

## 변경 범위

메뉴는 문자열이 아니라 배경 타일 그림이다. 은행 `F1D734`의 0번 원시 4bpp atlas `F1D8F4..F250F4`, 7번 압축 타일맵이 해당 화면을 구성한다. 기존 32×16 영역의 타일 180..183/1A0..1A3 여덟 개만 다시 그렸다. 달무리 8×8 글꼴의 ‘갈아입기’를 기존 배경 타일 28D/290의 무문자 무늬 위에 배치했다. 문자는 원래 팔레트 14번으로 표시한다. 네 글자가 원래 영역에 들어가도록 소형 글꼴을 사용했다.

최종 ROM은 `output/v1.1a-dev34-verified-01/ND3_B3TJ_K_v1.1a.gba`, SHA-256 `af29f6fbd8982bf4874c8c7149d48f106385ed64dbc7176274bcbdeec3a5cc2d`다. dev33과 비교한 실제 변경은 **145바이트**, 전부 이 여덟 타일 안이다. 타일맵, 팔레트, 코드, 데이터 포인터, 능력치, 다른 메뉴 그림은 바뀌지 않는다. 대사의 ‘변장’은 문맥이 다르므로 일괄 치환하지 않았다.

## 확인한 내용

- `source/costume_label_profile.json`에 원문과 채택어, 원본 atlas와 34개 메뉴 맵의 해시, 실제 로더·팔레트 변경 코드 경계를 기록했다. 이 34개 맵에서 대상 타일의 유일한 사용 위치는 7번 맵의 첫 메뉴명이다.
- `tools/verify_costume_label.py`는 512개 픽셀, 전체 atlas의 보호 영역, 34개 맵과 팔레트를 검사한다. 실제 원래 은행 조회와 DMA 큐가 atlas 30720바이트 및 7번 맵 1280바이트를 전달함을 실행해 확인했다. BIOS LZ77 동작은 경계를 검사한 모델이다.
- mGBA와 VBA Next에서 일반 버튼으로 선택/비선택 표시, 훌리오 선택, 검사 의상 선택, 확인, 갈아입기 연출, 의상 메뉴 복귀를 확인했다. 복귀 후 훌리오는 검사, HP8504/TP1097이었다. 기존판과 동일한 버튼·프레임 경로에서 각 코어 11개 화면, 총 22개 지점의 256KiB EWRAM이 모두 일치하며 화면 차이는 메뉴 글자 영역에만 있다.
- 새 게임·첫 저장·별도 프로세스 재로드도 양쪽에서 통과했다. 같은 코어의 dev33 저장 8192바이트와 네 화면은 그대로다. 누적 빌드의 분리 검사 29개가 통과했다.
- 사용한 해금 검토 세이브 원본은 수정하지 않았다. 합성 해금 상태에서의 표시/의상 변경 검사이며 모든 의상·정상 획득·전편 진행을 검증했다는 뜻은 아니다.

일본판 비교 화면은 한국어 이름이 든 검토 세이브를 사용하므로 주인공 이름 부분에 인코딩 차이가 보인다. 저장 이름과 무관한 원래 메뉴명 및 기능 설명만 이 비교의 원문 근거로 사용했다.

근거: `qa/results/costume-label-dev34/`. 캡처 재현 도구는 `tools/probe_costume_label.py`. 원본 일본판 및 기존 ROM은 보존했다.


## dev35: 메뉴 글꼴과 내부색 보완 (2026-09-13)

사용자가 지적한 소형 글꼴 차이를 수정했다. ‘갈아입기’를 48×16 영역에 배치하고 기존 메뉴의 12×12 글자 그림을 사용한다. ‘아’는 아이템, ‘입’은 새로입수, ‘기’는 기술에서 가져왔다. ‘갈’은 같은 크기와 테두리 색으로 작성했다. 초안에서 빠졌던 팔레트 1번 내부색을 복원하여 ㅇ·ㄱ을 포함한 세 원본 글자의 432개 픽셀이 배경을 제외하고 원본과 같음을 확인했다. 선택/비선택 팔레트는 기존 처리를 그대로 사용한다. 사용자 정정에 따라 logo.png는 기존 파일을 유지했다.

원본 atlas는 보존하고 0x1130000에 30848바이트를 복사한다. 원래 전용 8타일과 추가 4타일만 재작성한다. 추가 타일은 VRAM 0x06007800..0x0600787F로 다음 맵 0x06008000과 겹치지 않는다. 7번 맵은 0x1137880에 RLE로 저장하며 내용 차이는 가장자리 네 빈 칸의 타일 번호뿐이다. 은행 상대 오프셋 0/7과 0xC8C6C의 movs r2,#240을 #241로 변경하여 기존 DMA가 30848바이트를 복사하게 했다. 원래 로더의 실제 은행 조회·압축 종류 분기·DMA 큐·스택 복귀를 CPU 검사로 확인했다. BIOS RLE만 경계가 제한된 모델을 사용한다.

최종 ROM: `output/v1.1a-dev35-verified-02/ND3_B3TJ_K_v1.1a.gba`. SHA-256 `9b7b3c1594d079dddc607e270a59ddb235a4d9acaf6c16110a4bc1450e0c5f99`. dev34와의 29909바이트 차이는 위 연결·새 리소스 및 dev34의 원래 atlas 8타일 복원에 한정된다. 다른 원본 34개 압축 맵·팔레트·atlas 보호 영역은 그대로다.

mGBA와 VBA Next에서 일반 버튼으로 11개 지점을 각각 캡처했다. 선택/비선택, 의상 목록·확인·검사 변경·복귀 화면을 직접 관찰했다. 같은 코어의 dev34와 비교한 22개 중 21개는 메뉴 글자 영역 외 픽셀이 같다. mGBA의 캐릭터 선택 1개는 캐로의 움직이는 그림 영역에 535픽셀 차이가 있으며 문구·능력치 차이는 없다. VBA의 256KiB EWRAM은 11개 지점 모두 네 맵 칸 이외에는 같다. mGBA 전체 EWRAM의 동일성은 주장하지 않는다. 두 코어의 첫 저장 8192바이트는 각각 dev34와 같고, 별도 프로세스 재로드·아이템·설명 화면도 확인했다.

정확한 캡처·ROM 차이·저장 근거는 `qa/results/costume-label-dev35/`에 보존했다. 누적 빌드의 분리 검사와 실제 배포 적용기 검증은 해당 최종 빌드 및 패키지 결과에 연결한다. 모든 의상·전편·오디오 검증 완료를 뜻하지 않는다.
