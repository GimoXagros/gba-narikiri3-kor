# 인스펙트 아이의 별도 글자 출력

2026-09-09, v1.1a-dev26. 첫 임무에서 캐로를 학자로 바꾸고 훌리오 팀의 전투를 진행하자 인스펙트 아이 창에 일본어 항목명과 깨진 한글 적 이름이 나타났다. 이는 일반 소형 글꼴 두 경로와 다른 소비자다. 문자열 첫 바이트가 `12`인 세 항목은 기존 포인터 후보 검색에서도 누락됐다. 검색 후보 수나 가나 검색 결과 0을 전체 번역률로 해석할 수 없는 실제 사례다.

## 원인과 변경 범위

원래 `16854`는 자원 440을 로드한 뒤 `1697C`에 적 레코드를 전달한다. `1697C`는 `1021AC + 적 ID × 56`의 이름 포인터, 현재/최대 HP, 공격 속성, 여덟 내성 값을 선택한다. 그 결과를 `16A48`에서 16칸 폭의 affine byte map에 쓴다. 이 마지막 함수는 한 바이트만 처리하므로 새 한글 적 이름을 올바르게 읽지 못한다. `168C8`, `168F0`, `16934`의 속성 선택은 텍스트가 아닌 데이터 처리다.

`16A48` 입구만 새 출력기로 연결하고 세 항목의 포인터를 `공격:`, `내성:`, `약점:`으로 교체했다. HP 포맷, 적 ID와 표의 나머지 52바이트, 공격 속성 ID, 내성의 signed/unsigned 비교, 창 위치와 닫기 동작은 유지했다. v1.1의 항목 미번역과 v1.1a에서 추가한 한글 이름의 별도 출력 호환 문제를 구별한다. 일본어 원작의 게임 규칙 오류를 고쳤다는 주장은 아니다.

이 창은 205/206도 원래 적 표에서 이름을 직접 조회한다. 일반 적 이름 함수 `655C`의 저장 이름 분기와 혼동해 변경하지 않는다. 해당 212개 표 이름은 이미 번역된 값을 사용한다.

## 자원과 저장 공간

`1449E4`의 자원 440은 글꼴/팔레트/맵 282/283/284를 참조한다. 글꼴 `D86384`는 BIOS RLE 해제 후 15360바이트, 8bpp 타일 240개다. 원래 로더는 이를 `06008000`에 놓는다. 원본 해제 결과가 실제 전투의 VRAM과 일치함을 확인했다. 맵 `D882E8`은 15×9, 6프레임이며 원래 타일 인덱스는 모두 240 미만이다.

원래 글꼴 다음과 일반 UI 글꼴 `0600C000` 사이에 있는 16개 슬롯 중 F0..FE만 사용한다. 제목은 최대 9칸, 항목명은 각 한글 2칸으로 위치마다 타일을 고정한다. 새 영구 RAM이나 공유 캐시를 사용하지 않는다. 글자 픽셀은 기존 달무리 원본에서 읽고 원래 배경 A1/글자 AF로 반전 없이 출력한다. VRAM에는 16비트 단위로 쓴다. 원래 `51F04`의 256바이트 맵 전송 위치는 `0600F000`이다.

원본의 여덟 속성 한자 기호는 dev26에서 보존되어 있다. 기호의 한글 표시 정책과 다른 속성 표시 소비자 조사는 별도 남은 작업이다. 속성 숫자나 판정 코드를 번역 대상으로 삼지 않는다.

## 확인한 증거

- 정확한 dev26 SHA-256: `c9a06b914868d6abe84b7d03a5b54a0e75a7ea10b5dec480943f4c7099dec1b7`.
- 누적 재현 빌드의 전체 분리 CPU 검사 통과. 이 창은 원래 생산 함수/HP 포매터를 실행해 212개 이름, 9개 공격 속성 선택, 각 내성의 00/01/7F/80/81/99/FF 경계 등 280사례를 검사했다. 글자 위치 2792개, 전체 맵·테두리·스택·저장 레지스터·적 데이터·인접 VRAM 보존을 확인했다. 마지막 DMA만 모형화한다.
- 첫 검사 실패는 검사기의 보호 범위에 원래 맵 DMA 목적지 F000..F0FF를 포함했기 때문이다. 이 구간은 예상 맵과 별도로 비교하고 그 외 VRAM 보호를 유지하도록 검사기를 수정했다. 게임 오류나 추가 ROM 수정으로 집계하지 않는다.
- mGBA에서 dev24의 정상 중단 저장을 새 프로세스에 읽고 같은 컨트롤러 입력을 재생했다. frame 42202에 `그린 로퍼`, HP 580/580, 세 한글 항목을 직접 관찰했다. 원래 atlas와 적 상태 512바이트, 인접 VRAM은 dev24와 동일했다. RAM 개입과 다른 ROM의 상태 파일 가져오기는 0회다.
- frame 42444의 B로 닫은 화면은 dev24와 PNG 바이트까지 동일했다. A는 원래와 같이 이 창을 닫지 않는다. 후속 정상 전투에서 다른 적 이름과 HP가 표시되는 것도 관찰했다. 기록은 `output/v1.1a-dev26-inspect-mgba/inspection-observation.json` 및 입력/캡처에 보존한다.
- 두 PC 코어의 새 게임·첫 저장·새 프로세스 재로드·아이템 화면 8개를 직접 확인했다. 저장은 같은 코어의 dev25와 바이트 동일하고 시간은 mGBA 17733 / VBA Next 17728로 유지됐다.

추가로 전투 뒤 정상 중단 저장 `73d7aa6ca8e0d6b064f5f0edcd1597033dc61687c585478da4da28c40687165d`을 두 코어의 새 프로세스에서 불러왔다. 훌리오의 검사 변장, 애플 구미 네 번 사용, 재전투 후 캐로의 기술을 직접 선택하여 양쪽에서 한글 정보창을 관찰했다. 실제 적 레코드와 출력값은 두 코어 모두 505/580이다. 처음에는 VBA 화면의 숫자를 580으로 잘못 읽었으나, 두 VRAM 맵의 원래 숫자 타일 역조회가 모두 `HP  505/  580`이며 행 바이트도 `11190505433e43d1050543463e`로 같음을 확인했다. 이는 관찰 기록의 정정이며 게임 오류나 수치 변경으로 집계하지 않는다. 각 `output/v1.1a-dev26-post-inspect-*/manual-inspection-observation.json`에 해시와 실제 적 레코드 값을 남겼다.

매직 렌즈 아이템을 통한 같은 창 진입, 모든 자원 수명·전편 플레이는 아직 완료되지 않았다. dev26은 개발판이며 전체 무오류나 100% 검수 완료를 뜻하지 않는다.
