# 음악 제목과 특수 필드 이름

v1.1a-dev25에서 음악 제목 12개와 특수 필드 이름 1개를 번역했다. 대상 ROM SHA-256은 `6feafc44f71982f8739dd3568b381b2747d5ccc2ccbf3755ae83b09b90a42037`이다.

D441BC는 16바이트 음악 레코드 12개다. +00 악보 포인터, +04..+0B 곡 ID/타이밍을 보존하고 +0C 제목 포인터만 선택했다. 0809D7C6의 실제 ID 조회가 이 제목을 08016528로 넘긴다. 080167B0이 19글자 기준으로 가운데 정렬한 문자열을 객체의 +04..+2F(44바이트)에 복사하고 08016780/080014F4가 기존 큰 글꼴로 표시한다.

번역은 마피, 리블 래블, 드래곤 버스터, 메트로 크로스, 스카이 키드, 드래곤 스피릿, 겐페이 토마덴, 판타지아, 데스티니, 이터니아, 데스티니 2, 심포니아다. 한국어 정식 제품명의 확인을 주장하지 않는 원문 음역이며, 원문과 대응은 translations/notices.json에 남겼다. 원래 폭 계산은 ASCII 공백을 세지 않으므로 제목의 공백은 지원되는 전각 공백으로 넣었다. 기존 정렬 코드는 보존한다.

080A55F4의 인물 ID 56/57은 화자 표 대신 별도 일본어 `ﾒﾙ･ﾃﾞｨｵ`를 반환했다. 이 리터럴만 `멜/디오`로 바꿨다. ID 73/74의 숨겨진 이름 `???`, -1의 빈 이름, 나머지 화자 조회는 그대로다. 080A5638 계열의 원래 8칸 창에서 한 이름 또는 두 줄 이름을 출력하는 실제 분기를 검사했다.

tools/verify_notices.py는 두 글꼴 모드에서 음악 12개의 두 표시 위치, 합계 48회 가운데 정렬/복사/대형 출력과 568개 글자 위치를 확인했다. NUL을 포함한 최대 문자열은 27바이트로 44바이트 공간 안에 들어간다. 원래 지도 앵커와 상대 글자 좌표를 구분해 검사한다. 음악의 내용이나 효과 수치는 수정하지 않는다. BIOS CpuSet의 고정된 3840바이트 글꼴 버퍼 채우기만 CPU 시험용으로 모사한다.

특수 이름 조회 10개, 실제 한 줄/두 줄 소형 출력 8개도 통과했다. 초기 검사 실패는 이 BIOS 처리와 시험 기대값의 좌표/줄 시작점 모델이 빠진 탓이었다. 이를 보완하는 동안 ROM 바이트는 바뀌지 않았다. 정리한 소스에서 다시 만든 output/v1.1a-dev25-verified의 모든 누적 CPU 검사가 통과했다.

두 PC 코어의 도입부/첫 저장/새 프로세스 재로드/아이템 8개 화면도 확인했다. 같은 코어의 dev24와 첫 저장 파일이 바이트 동일하다. 음악 이벤트와 멜/디오 정상 등장 장면의 화면 확인은 남아 있다. 분리 소비자 검사나 앞부분 재생 결과를 전편 검증으로 확대하지 않는다.
