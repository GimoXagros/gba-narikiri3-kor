# v1.3 후보 검증 요약

상태: **WORK_IN_PROGRESS / UNPUBLISHED_REVIEW**. 이 문서는 공개 준비 자료이며 필수 게이트가 끝나기 전에는 발행하지 않는다.

## 후보와 재현

RC16은 16,777,216 bytes, SHA-256 `decedfd15fafe621be14edd2375a0c9f8f23ce99fceaf3f1abf44a00347526e4`이다. 누적 BPS는 525,183 bytes, SHA-256 `961f3142f93182e5d708dcbd82dc022d208549492880ae2deb4c801ab32e462f`이다. 원본 일본판·개발용 1.1 IPS·생산 소스에서 기존 OPT16/OPT32 체크포인트를 정확히 재현한 뒤 후보를 생성했다. 최초 통합 커밋의 별도 clean checkout A/B는 ROM·BPS가 같았고 실제 재적용도 정확했다. 이후 메타데이터 커밋은 별도 최종 manifest에 연결한다.

26개 보호된 쓰기 범위 안에서만 OPT16과 2,543바이트가 다르다. 변경된 그림은 원래 소비 스트림의 실제 길이와 명시된 소유 공간으로 연결했다. 수정 구간 밖 전체 바이트, 기존 메뉴 성능 코드와 지정한 공유 자원은 보존했다. 구현자의 생성 검사와 독립 포인터·수명·자연 화면 검사는 별도 근거이다.

## 한정된 PC 확인

- 고정 RC16/OPT16 메뉴 시나리오에서 아이템 6,136개와 도감 6,264개 표본의 창·선택 ID·문자 영역이 같았다. 전체 게임 속도나 일본판과의 전체 동등성 주장이 아니다.
- 정확 후보·mGBA core·고정 입력 trace의 첫 저장 관측 두 회는 각각17,759였고 체크섬과 시간·체크섬을 제외한 저장 내용이 기준과 같았다. 이 조합에만 허용 오차0의 관측 계약을 추가했다. **기존17,767±3 검사의 FAIL은 그대로 보존한다.** 원래 논리 타이머 코드는 바뀌지 않았고, 독립 이전 비교에서 렌더링 중 완료된 논리 업데이트 수 차이가 관측됐다. 실기 시간 동등성은 주장하지 않는다.
- 정확 후보의 재저장·콜드 재로드·마을 상담 경로는 OPT16과 관측 영상 및 저장 결과가 같았다. 전투40,527프레임에서 달랐던1,230개 모두 독립 검토가 실제 바뀐 자원 bytes와 OAM의4bpp 원천 픽셀에 정확히 귀속했다. town65/80 쌍120프레임, town67/82 쌍290프레임, field1 820프레임이며 승인 자원 원천 밖의 차이는0이다. BG VRAM·OAM·팔레트·텍스트 버퍼·주 저장 본문·41캐릭터 구조는 같았다. 이는 관측 경로의 승인 그림 차이에 대한 판정이며 전체 영상 동일성 또는 전체 게임 검증은 아니다.
- 별도 PRE16→OPT16의 과거3,866프레임 차이와 strict 비교 FAIL은 유지한다. 명찰 과도 표시·wipe 경계 등 시각 분류와 미확정 개별 인과를 구분한다. 새 후보 전투의1,230개 차이와 합산하거나 같은 모집단으로 설명하지 않는다.
- RC16/FIX32의 네 고정 경로는 첫 영상 프레임만 달랐다. 초기 덤프에서 RC16은 forced blank(`DISPCNT 0x0483`), FIX32는 active(`0x0403`)였고 관측 frame2~10은 같았다. 전체 raw strict 비교의 첫 프레임 FAIL을 지우지 않으며 이 경로 밖으로 예외를 확대하지 않는다.
- 합성 해금 저장의 조작만으로 편성→캐릭터 목록→L/R→취소 경로를 확인했다. 비교 화면13개 중 안내가 바뀐09/10만 `[192,2,222,10]` 영역이 달랐고41캐릭터 값은 유지됐다. 전원이레벨99인 합성 저장이라 정렬 순서가 같았으며, 서로 다른 레벨의 실제 CPU 정렬 검사는 별도 근거이다. 정상 진행 또는 실기 검증이 아니다.
- 같은 합성 저장에서 정보 메뉴45개 지정 화면을 OPT16과 비교했다. 3개 화면의 공유52 글자70픽셀만 달랐고 모든 화면의 OAM·팔레트·41캐릭터 구조는 같았다. 앨범·도감·상태 세부 정보, 페이지 이동·취소, 카드·재료·레시피·아이템/장비·기술·편성의 지정 화면 범위이며 전체 영상 비교는 아니다. 필드 의상 선택의 group7은 독립 검토가 실제52/53 자원과 VRAM을 대조했다.
- 넓은 헤더4개는 실제 mapID1/5/10/30→selector1/5/10/16→자원1/5/9/15 사슬을 조작 경로와 실제 VRAM·OAM으로 확인했다. 각640bytes,20타일·3컴포넌트의 화면 내 표시와 팔레트 원천 픽셀 불일치0을 검증했다. 최초 세 경로는 명시적 합성 chapter2/6/10 저장이며 마지막은 합성 chapter22 해금 저장이다. 정상 스토리 진행이나 실기가 아니며 취소·재진입 수명 검토는 별도 추가 보고서로 판정한다.
- 기존 제공 검수용 중단 저장에서 콜드 로드 후 필드 메뉴·의상 선택·취소·실제 의상 변경·필드 복귀를21개 화면과5,229프레임의 조작으로 확인했다. 원본 저장 변경·RAM 개입·상태 로드는 없다. 이 저장의 생성 이력을 정상 플레이로 다시 분류하지 않는다.

## 자원 대장과 공개 소스 범위

기존 구현13·문맥6·넓은 메뉴4의 합집합은23개 원자원 ID이다. 후보에서 이 집합 안의12개 자원 몸체와 집합 밖 보조52가 바뀌었다. 51/54는 그대로이며52/53으로 공유 안내를 고친다. 정렬102를 바꾸고103은 보존한다. 논리 조치 수와 물리 자원 변경 수를 혼동하지 않는다.

페이지55/56와 통신84/85의 정적 소비자 코드는 확인됐지만 자연 호출 문맥은 미관측이다. 추측 수정하지 않으며 실제 미사용이 증명되었다고 처리하지 않는다. 넓은 헤더4개는 UI 커서와 별도의 검은 BG 지명 대신 실제 진입 임무의 그래픽 헤더·VRAM 자원을 근거로 확인했다.

기존 공개 빌드 입력의 부분 교정 대장은 전체 일본어 대본과 다르다. 5,208개 reviewed-record는 offset 값이고4,788개 고유 pair는 숫자 메타데이터이다. 기존1,363/403 correction group에는 해당 부분의 일본어 구절이 있다. 403-group Markdown은386개 offset을 명시하며 전체425 occurrence 주소를 열거하는 문서가 아니다. 전체4,788쌍 본문 덤프·개인 자료·별도 폰트 바이너리는 새 공개 소스나 자산에 넣지 않는다.

## 남은 공개 게이트

넓은 헤더의 취소·재진입 수명 추가 판정, 과거3,866프레임 비교의 잔여 인과, 새 후보의 최소 실기 재검수와 Astra GO가 남아 있다. 명시적 ZIP 허용 목록·실제 동봉 적용기·잘못된 원본과 손상 패치 거부·기존 출력 보호·중첩 압축0은 검수용 자산에서 확인했고, 두 clean 빌드의 패키지 자산도 같았다. 향후 최종 배포 커밋·태그·원격 자산은 다시 정확한 해시에 연결한다. 실제 관측 범위 밖의 전편 완주·무오류·모든 기기 지원은 주장하지 않는다. 이전 사용자의 결함 신고는 새 후보의 실기 PASS가 아니다.
