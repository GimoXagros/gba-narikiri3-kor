# 번역 대상과 비텍스트 구분

검색 결과를 곧바로 삽입 대상으로 쓰지 않는다. 원본 바이트, 실제 참조 필드, 출력 코드, 표의 범위와 제어를 확인한 항목만 `source`와 `translations`에 채택한다.

## 음성 데이터를 문자열 참조로 오인한 후보

최초 정렬 포인터 검색은 1000C4..1C8000에 대한 8263개 후보를 만들었다. ROM 전체의 임의 4 bytes도 주소 모양과 일치할 수 있으므로, 이 수는 번역률 분모가 아니다.

원래 음성 코드 `080DBC84/080DBC86`은 ToneData+4의 WaveData를 채널+24로 옮긴다. 믹서 `080DB2CA/080DB302..30A`는 이 헤더+10부터 +C 길이만큼 샘플을 읽는다. 이 실제 코드와 ToneData 참조를 대조해 `1CB9D8..6EC700`의 PCM 754개를 확인했다. 샘플 뒤의 종결 바이트와 4-byte 정렬도 다음 헤더 및 마지막 노래 헤더와 일치한다. 비교 자료는 [m4a 구조 선언](https://github.com/pret/pokeemerald/blob/master/include/gba/m4a_internal.h)이다.

`tools/classify_text_candidates.py`의 결과에서 349개 후보는 이 검색에 잡힌 참조가 모두 PCM 샘플 내부였다. 그중 18개는 기존 한국어 바이트를 문장 중간부터 디코딩해 오류처럼 보이던 경우다. 실제 기술 표에 참조가 있는 나머지 디코딩 실패 2개는 기존 기술명 18개 보완에 포함되어 있다.

음성의 우연한 바이트를 참조로 인정하지 않는 것이며, 해당 주소에 실제 문자열이 존재할 가능성 자체를 지우지 않는다. 다른 정상 호출자가 발견되면 그 근거로 별도 채택한다. 7914개 남은 후보도 확정 문자열·미번역 수가 아니다.

`source/nontext_profile.json`은 5377320 bytes의 PCM 은행을 보호한다. 현재 일본판·v1.1·v1.1a에서 해당 바이트가 동일하며, 누적 빌드는 이 영역의 변경을 거부한다. 범위 밖의 데이터까지 모두 분류했다는 뜻은 아니다.

## 현재 채택한 소형 표시

910개 이름 필드, 팀 칭호/보너스 54개 슬롯, 선택 UI 23개 리터럴/표 필드를 채택했다. 54개는 원래 58개 팀 규칙과 조회 코드에 근거한다. 칭호 23번 및 보너스 9/11번은 이 규칙에서 선택되지 않으므로 슬롯은 보존·번역하되 정상 게임의 도달을 주장하지 않는다.

기존 문장 및 그래픽, 중복 이름 표, 디버그 화면, 전체 호출 경로는 별도 분류·검수 중이다. 채택 수의 증가를 100% 번역의 근거로 사용하지 않는다.
