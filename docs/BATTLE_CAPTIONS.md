# 전투 아이콘 안내의 구조와 검증

2026-09-09, v1.1a-dev13. 대사 스캔과 구분한 실제 그래픽 텍스트 4개다.

첫 전투에서 Select로 여는 메뉴를 양쪽 PC 코어에서 관찰했다. 원래 안내는 とくぎ / さくせん / どうぐ / たいれつ이며, 특기 / 작전 / 아이템 / 대열로 번역했다. 마지막 항목은 실제 진입 화면의 대열 변경과 일치한다. 초기에 도주로 추측했던 것은 폐기했다.

## 원래 소비 경로

- 0801769C..176B2의 선택 경계는 0..3이다. 버튼 입력/동작 분기 코드는 변경하지 않았다.
- 080175A4가 08003444에 그래픽 은행 D36058의 인덱스 3을 전달한다. 은행은 개수 8, 상대 오프셋 8개이며, 인덱스 3은 D384BC..D38BBC의 0x700 bytes, 56개 4bpp 타일이다. 이어지는 원래 DMA 전송과 타일 할당 크기를 보존한다.
- 113D7C의 프로필은 프레임 표 7C1CB0, 18개 프레임, 56개 타일을 지정한다. 7C1B78..7C1CB0의 실제 프레임 서술자가 아이콘/커서/배경/글자 타일의 형태와 번호를 결정한다.
- 글자 그림 12개는 D38A3C..D38BBC의 하위 풀이다. とくぎ와 どうぐ가 と/く/탁점을 공유하므로 눈에 보이는 한 타일만 교체하면 다른 안내가 손상된다.
- 7C1DDC의 포인터 4개가 각각 7C1D3C/5C/7C/9C의 32-byte 배치를 선택한다. 각 배치는 8개의 `(frame, x, y, reserved)` 부호 있는 바이트 레코드다. 08017C88은 프레임 0을 숨기고 원래 아이콘 좌표와 글자 오프셋으로 8개 오브젝트를 배치한다.
- 원래 아이콘/커서/배경 프레임과 팔레트, 13개 오브젝트 할당, 메뉴 선택 및 전투 동작 코드는 보존했다. 선택한 한글 9자의 그림과 네 안내 배치만 수정한다. 사용하지 않는 글자 슬롯은 미사용으로 남기며 전체 그래픽 번역률의 분모로 삼지 않는다.

## 확인 결과

정확한 dev13 ROM SHA-256은 `2eb8ad6b861eb581070bab1a6d4b7bd60bb36af6186a2a54c32dee27d3a21251`이다.

- 원래 상대 은행 조회와 08017C88 배치 코드를 분리 CPU에서 실행했다. 네 선택과 한글 9자의 실제 타일 픽셀, 좌표, 프레임 형태/팔레트를 검사했다. 아이콘/배경/동작 코드 보존 검사도 통과했다.
- `qa/traces/first-battle-menu.jsonl`은 첫 EEPROM 저장부터 첫 전투 메뉴까지의 정상 입력 40831프레임을 기록한다. RAM 개입이 없다. mGBA와 VBA에서 각각 재실행한 뒤 네 안내를 모두 관찰했다.
- 이전 dev12의 같은 코어/같은 입력 시점과 화면을 비교했다. 달라진 픽셀은 안내 영역에만 있었고, 아이콘·배경·전투 상태 표시·캐릭터 영역은 같았다. 코어 간 전투 진행은 몇 프레임 차이가 있으므로 서로 다른 코어의 전투 상태가 항상 같다는 뜻은 아니다.
- 로컬 증거는 `output/v1.1a-dev13-battle-{mgba,vba}/caption-observation.json`과 입력 기록/캡처에 있다. 대열 화면 진입/복귀와 전투 중 아이템 선택 후 목록도 추가 관찰했다.

이는 첫 전투 메뉴의 네 안내 검증이다. 전편 전투/모든 상태/모든 그래픽 검증 완료로 확대하지 않는다.
