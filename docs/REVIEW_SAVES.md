# v1.1a dev32 검토용 해금 세이브

사용자가 2026-09-12 요청한 검토용 수정 세이브다. 원본 플레이 세이브는 읽기만 했으며, ROM은 변경하지 않았다. 정상 진행·클리어·전체 번역 검증의 근거로 사용하지 않는다.

## 제공 파일

- `ND3_v1.1a_review_postgame.sav`: 챕터 값 22와 원래 디버그 챕터 동기화 함수로 클리어 후 상태를 구성했다. 수집 메뉴와 후반 상태 검토용이다.
- `ND3_v1.1a_review_collection.sav`: 첫 마을 저장의 챕터 값 1을 유지한 수집 요소 검토용이다. 초반 메뉴와 제작 등을 비교할 때 사용한다.

두 파일은 표준 8,192바이트 EEPROM 저장이다. 게임 내 불러오기를 사용하며 에뮬레이터 강제 저장 파일이 아니다. 배포 위치는 `output/검토용_해금세이브_v1.1a_dev32.zip`이다.

| 요소 | 적용 및 확인 범위 |
| --- | --- |
| 코스튬 | 유효한 착용 코스튬 89개, 게임 화면 89/89 |
| 몬스터 도감 | 원본 개체 212개의 발견/상세 기록, 중복을 합치는 게임 화면 154(154)/154 |
| 캐릭터 명감 | 실제 목록 37개, 게임 화면 37/37 |
| 동료 | 초기화된 41개 동료 슬롯 모두 가입, 레벨 99, HP/TP 회복 |
| 아이템 | 없음(ID 0)을 제외한 122개 ID 각각 15개, 재료·석판 포함 |
| 요리 | 22개 레시피, 동료별 요리 숙련도 100 |
| 자금 | 9,999,999 갈드 |

리온과 쥬다스도 동시에 검토할 수 있다. 정상 진행의 양자택일 조건을 재현하는 세이브가 아니다. 89개 코스튬은 ID 1..93 중 미랄드(41), 딤로스(43), 도박꾼(60), 자바바(87)를 제외한다. 빈 항목(0)과 등장 전용 훌리오/캐로(94/95)를 추가하지 않았다. 각 성별의 착용 제한은 게임의 원래 목록 필터를 따른다.

## 생성 근거

`tools/build_review_save.py`는 아래 두 입력 해시를 고정하고 새 출력 폴더만 허용한다.

- dev32 ROM: `1051612d3027c315596e28a5eb78451287bde5926e57d45268537c90c29b56ca`
- 정상 첫 저장: `312bb57555b6d405d235d1affe240b29fedc0c73ddfa1e125607efb37d94e6c2`

EEPROM의 각 8바이트를 역순으로 풀면 일반 저장(0..EFF), 중단 저장(F00..1DFF), 공통 수집 기록(1E00..1FFF)이다. 일반 저장은 `02001D80`에 대응한다. 원래 포인터 초기화 6118, 역직렬화 7410, 직렬화 7450을 사용했다. 아이템 663C, 가입 7D48, 레벨 상승 76C0, 회복 79F8, 요리 숙련 6374, 갈드 6258, 플래그 812C를 실제 Thumb 코드로 실행했다. 레벨 숫자만 바꾸지 않고 원래 성장 계산을 거쳤다. BIOS Div 진입점 DD42C만 부호 있는 정수 나눗셈으로 모사한다.

플래그 벡터는 일반 저장 +9E0의 400바이트다. 몬스터 1..424, 코스튬 1A9+ID, 동료 266+슬롯, 명감 209+각 레코드의 실제 ID, 요리 678..68D를 설정했다. 이야기 플래그 전체를 FF로 채우지 않았다. 클리어 후 파일만 959C(챕터 22), A6C68(원래 챕터 동기화)를 실행했다. A6C68이 후반에 몬스터 발견 비트 23 또는 24를 지우므로 이후 몬스터 수집 비트를 복원한다. 이 동작은 디버그 함수의 관찰 결과이며 정상 게임의 오류로 분류하지 않는다.

공통 수집 블록은 8C7C의 원래 배치에 맞춰 플래그 400바이트, 갈드, 시간을 넣는다. 헤더 NARIKIRI/revision 0131CD45와 본문의 32비트 합을 기록한다. 두 유효 블록은 원래 검사 함수 8A08을 통과하고 체크섬 한 비트를 손상시키면 거부된다. 중단 저장과 그 밖의 해석되지 않은 데이터는 보존한다. 변경 가능 오프셋을 제한하고 실제 변경 목록을 기록한다.

## PC 확인

`tools/probe_review_save.py`와 `qa/results/review-save-dev32/report.json`에 입력·코어·결과 해시를 기록했다. mGBA 0.11-219-e31759b 및 VBA Next 1.0.2에서 **두 파일 × 두 코어** 각각 게임 내 저장 완료까지 기다린 뒤 내보내고, 새 프로세스로 다시 불러왔다. 재저장 파일에서도 아이템 수량, 레벨, 동료·도감·코스튬·요리 플래그가 유지된다. 실제 화면의 수집 수치와 마지막 요리를 확인했다. 동료 선택 목록은 postgame 파일에서 확인했다. collection 파일은 초반 단계에 따른 넣기/해산 제한을 유지해 같은 입력에서 목록이 열리지 않는다. 실행 중 RAM 개입은 없다. 입력 세이브 자체가 수정본임은 별도 명시한다.

초기 탐색 `review-save-postgame-*-01`의 몬스터 153/154는 위의 챕터 동기화 부작용을 발견한 미완성 표본이다. `review-save-resave-postgame-mgba-01`은 저장 대기가 240프레임으로 짧아 아직 저장 중이었던 표본이다. 제공 파일에는 보정을 적용했고, 최종 재저장 검사는 1,800프레임 대기 후 저장 완료와 새 프로세스 재로드를 확인했다. 초기 표본을 성공 근거로 사용하지 않는다.

## 검토 범위의 한계

수집 요소의 해금과 PC 저장 호환을 확인한 파일이다. 모든 이야기 분기·NPC 이벤트·전투·엔딩을 전부 순회한 완주 세이브는 아니다. 클리어 후 값이 설정되어 있어도 모든 스테이지 재진입과 이벤트 조합이 안전하다고 보증하지 않는다. 초반 이벤트 검토에는 collection 파일을 사용하고, 편성 검토에는 postgame 파일을 사용한다. 미번역·글자 잘림·장면 오류 검토를 위한 도구이며, v1.1a 패치의 100% 번역 완료 또는 프리릴리즈 승인 자료로 간주하지 않는다.
