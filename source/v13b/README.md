# v1.3b 표시 폭 변경 입력

`tools/build_v13b.py`는 일본판 원본과 기존 IPS에서 v1.3a까지의 소스 빌드를 재현한 다음 이 변경을 적용한다. 개발 중 생성한 ROM을 배포 빌드의 입력으로 사용하지 않는다.

- `dialogue.json`, `descriptions.json`, `large_ui.json`: 원래 바이트 길이와 시작 위치를 유지하는 공백·줄바꿈 변경.
- `performance/`: 글자 픽셀 출력과 확인된 목록의 타일 재사용 경로.
- `consumers/`: 큰 글씨 이름, 임무 조건, 자막 및 동적 표시 경로의 범위가 제한된 처리.
- `small-ui/`: 확인한 목록·안내문 표시 경로의 공백 폭 처리. 저장된 이름 코드와 숫자 정렬 공백은 유지한다.
- `native_context.s`: 도감 상세 화면의 기본 글자 처리에서 한 번의 출력에 한정해 타일 정보를 공유한다.
- `numeric_prefix.s`, `numeric_prefix.ld`: 확인된 도감 번호 열의 숫자 타일을 직접 배치한다. 호출 위치·범위·창 형식이 다르면 기존 처리를 사용하며, 화면 갱신 표시와 숫자 변환 임시 상태도 보존한다.
- `boot_rle.s`: 기존 첫 화면과 동일한 비트맵을 복원하는 압축 해제 코드. 확보한 공간은 표시 코드에 사용한다.
- `preservation.json`: 최종 단계에서 확인할 문자열 시작·종료 위치, 문자열 포인터 필드, 변경 금지 표.

큰 글씨의 `16 01`과 `17`은 반각 공백, `18`은 공백을 더하지 않는 줄 연결에 사용한다. 기존 페이지·대기·변수 삽입 제어는 유지한다. 효과와 조건처럼 별도 행으로 구분되는 내용은 일반 문장의 자동 줄바꿈과 구분한다.

이름 저장 영역과 키보드는 변경하지 않는다. 공유 이름 데이터는 검증된 표시 경로에서만 임시로 변환한다. 숫자 열과 사용자 이름의 정렬 공백은 일반 단어 사이 공백과 구분한다.

최종 빌드는 16,777,216바이트를 유지해야 하며, 마지막 변경 뒤에도 보존 검사에 통과해야 한다. 실행 검증과 배포 판정은 이 소스 설명 자체로 성립하지 않으며, 최종 후보 해시에 연결한 별도 기록을 따른다.

## 목록 배치 출력의 범위와 검증

공백 없는 한글 이름을 묶어 출력하는 경로는 한글 다섯 글자 이상인 확인된 이름에만 적용한다. 한 글자 폭은 기존 8픽셀을 유지한다. 네 글자 이하, 공백 포함, ASCII·다른 문자 혼합, 제어 코드 포함 문자열은 같은 대상이라고 가정하지 않는다. 저장 문자열이나 이름 저장 영역을 일괄 재인코딩하지 않는다.

읽기 전용 조사에서는 아이템 123개 중 4개, 몬스터 원시 테이블 212개 기록 중 13개가 이 조건에 해당했다. 실제 검수 저장의 154개 도감 목록에는 그중 9개가 포함된다. 원시 테이블 번호와 화면 도감 번호는 다르며, 합성 저장으로 항목을 표시한 사실이 자연 진행 중의 모든 해금 경로 검증을 뜻하지 않는다.

타일 슬롯이 모두 사용 중인 경우에도 기존 대체 출력과 커서 이동 계약을 지켜야 한다. 직전 후보의 124슬롯 압박 검사에서 발견된 조기 반환 문제를 수정했고, 최종 후보의 28개 타일 압박 사례에서 기존 픽셀과 커서 위치의 일치를 확인했다. 소비자·대사 검사는 변경된 ROM 해시마다 다시 수행하며 이전 후보의 통과 결과를 자동 적용하지 않는다. 정확한 후보 식별과 나머지 게이트 상태는 `docs/FINAL_VALIDATION_V1_3B.md`를 따른다.

포맷 임시 버퍼와 화면 갱신 플래그를 구분한다. 확인된 도감 콜백 재현에서 다음 포맷 전 임시 버퍼를 읽지 않았다는 관측은 다른 호출부에도 적용되는 전역 수명 증명이 아니다. 화면 갱신 플래그 `03001461`은 계속 읽히므로 기존 의미를 보존해야 한다.
