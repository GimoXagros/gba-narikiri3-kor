# 특기 화면 상단 그림

2026-09-09. v1.1a 개발판의 제한된 그림 검증 기록이다.

원본의 ‘とくぎのセッティング’, ‘とくぎをつかう’와 해당 모드의 동작을 대조하여 ‘특기 설정’, ‘특기 사용’으로 정리했다. K1.1에도 한국어 그림은 있었으나 작은 획과 윤곽 때문에 읽기 어려웠다. 기존 문구를 미번역으로 집계하지 않는다.

## 구조

- C90F8의 type 3/4가 C918C/C91A0에서 각각 45·46·47 / 45·48번 그림을 선택한다.
- F1D734의 111개 상대 포인터 중 해당 4개만 새 압축 그림으로 연결한다. 이전 압축 자료는 보존한다.
- 각 그림은 원래와 같은 BIOS RLE 형식, 128 bytes, 32×8이다. 새 자료는 길이가 정확히 맞는 128-byte 리터럴 블록이며 확장 영역 10C0000..10C0220에 배치한다.
- 원래 F1D0E0/F1D104의 3/2개 부품, x=0/20/52, 화면 기준 x=48/68, y=0을 보존한다. 세 번째 설정 그림은 투명 타일이다.
- 팔레트와 배치 코드는 수정하지 않는다. 원래 짙은 파랑 4번(4906)을 획으로 사용한다. 15번 흰색으로 만든 dev16은 밝은 패널에서 대비가 부족해 채택하지 않았으며, dev17에서 수정했다.

## 검증

실제 Thumb type 분기, 그림 크기 조회, 상대 포인터 조회, scratch 할당, 압축 해제 분기, DMA 대기열을 실행했다. 2개 제목/5회 로드/8개 한글 픽셀과 전송 범위를 검사했다. BIOS 해제는 길이를 제한하는 해석기로 대체하고, 독립 OBJ 할당과 합성 호출 경계를 사용한 분리 검사다.

dev17 SHA-256: ef7dbb6167e809f41c72546564cf9338e337ca02e2ff5b111c017f665995f4b7.

mGBA와 VBA Next에서 정상 입력으로 첫 전투의 설정 화면과 사용 화면을 모두 관찰했다. 변경된 이름은 읽을 수 있으며, 좌우 전환 후 사용 목록과 SELECT ON/OFF 안내가 표시된다. 두 코어의 output/v1.1a-dev17-battle-*/skill-header-observation.json에 정확한 산출물과 이미지 해시를 기록했다. RAM 수정은 없다.

K1.1의 46번 RLE 마지막 블록은 단순 블록 단위 해석 시 선언 길이보다 1 byte 길다. mGBA의 BIOS 구현은 남은 길이를 제한하므로 이 차이를 PC 메모리 손상으로 단정하지 않는다. 검토한 구현: https://raw.githubusercontent.com/mgba-emu/mgba/master/src/gba/bios.c 의 _unRl. 전체 원본 그래픽의 오류 검증을 마쳤다는 의미도 아니다.
