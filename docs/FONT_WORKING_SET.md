# 소형 글꼴 저장 공간의 실제 참조량

현재 소형 글꼴은 124개 타일을 재사용한다. 표시 중인 글자를 지우지 않도록 원래 1024칸 그림자 맵의 참조를 모두 보호한다. 125번째 새 글자를 담을 공간이 없을 때 `?`를 표시하는 개발용 진단 동작은 아직 최종 배포 조건을 충족하지 않는다.

`measure_font_working_set.py`는 PC 코어가 각 프레임을 끝낸 직후 읽기만 수행한다. `03000054/58`의 현재 글꼴 주소와 타일 기준값, `03000060`의 2048바이트 그림자 맵에서 두 저장 구간 70..AD/B0..ED의 참조 수를 센다. 최대값이 증가하면 원래 그림자 맵·글꼴·화면과 해시를 기록한다. 에뮬레이터 코드, ROM, 작업 RAM과 저장 값은 변경하지 않는다.

dev30의 측정 결과:

| 정상 입력 재생 경로 | 코어 | 프레임 | 초기화 전 제외 | 최대 참조 칸 |
|---|---|---:|---:|---:|
| 이름 입력 후보판·이름 확정·도입부 | mGBA | 35879 | 301 | 102 |
| 같은 이름 입력 버튼 순서 | VBA Next | 35879 | 301 | 102 |
| 첫 저장 재개·첫 전투 승리·의상 변경·중단 저장 | mGBA | 48282 | 301 | 32 |

이름 입력 최대값은 각각 프레임 22006/22008에서 관측됐다. 두 그림자 맵 SHA-256은 `27cf9f0985a6888d97b66d126303766285c8860010da456d0285af3bcd402953`으로 같다. 해당 최대값의 두 후보판 화면도 직접 확인했다. 임무 경로 최대값은 화면 전환 중의 그림자 맵이므로 이 32개가 모두 그 순간 화면에 보인다고 해석하지 않는다.

측정기를 넣어 재생한 임무 경로의 최종 화면 SHA-256 `3f94698a0a89b5c5b71e0ecf0b6cf8a03cdec9234bc28d4ee3ebdafd89959824`와 중단 저장 SHA-256 `128c85481e583c1e2f74b20974097599ae15446dabf01977a1aaf89e14eb0d80`은 측정기 없이 실제 진행한 dev30 결과와 각각 바이트 동일하다. 모든 경로에서 RAM 변경은 0회다.

보고서는 `qa/results/dev30-font-working-set`에 보존한다. `portable-traces.json`은 로컬 기록에서 버튼 요청만 분리한 `qa/traces/font-*.jsonl`과 원래 요청 순서의 해시를 연결한다. 두 키보드 경로의 버튼 순서는 동일하다. 임무 경로는 dev30 첫 저장 `03850ed9…48752`를 입력으로 사용한다. 최초 측정 뒤 추가한 최종 화면·저장 내보내기는 임무 재생에서 확인했으며, 앞선 키보드 보고서에는 이 두 항목이 없다.

한계: 프레임 내부에서 잠시 늘어나는 참조량, 다른 메뉴·도감·제작·상점·후반 전투와 모든 글꼴 로더의 수명은 이 측정으로 확정할 수 없다. 참조 수만으로 출력 글자의 픽셀 정확성도 증명하지 않는다. 따라서 위 수치는 제한된 경로의 실측이며 전체 게임의 최대치나 100% 검증 선언이 아니다.
