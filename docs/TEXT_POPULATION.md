# 번역 대상과 비텍스트 구분

검색 결과를 곧바로 삽입 대상으로 쓰지 않는다. 원본 바이트, 실제 참조 필드, 출력 코드, 표의 범위와 제어를 확인한 항목만 `source`와 `translations`에 채택한다.

## 음성 데이터를 문자열 참조로 오인한 후보

최초 정렬 포인터 검색은 1000C4..1C8000에 대한 8263개 후보를 만들었다. ROM 전체의 임의 4 bytes도 주소 모양과 일치할 수 있으므로, 이 수는 번역률 분모가 아니다.

원래 음성 코드 `080DBC84/080DBC86`은 ToneData+4의 WaveData를 채널+24로 옮긴다. 믹서 `080DB2CA/080DB302..30A`는 이 헤더+10부터 +C 길이만큼 샘플을 읽는다. 이 실제 코드와 ToneData 참조를 대조해 `1CB9D8..6EC700`의 PCM 754개를 확인했다. 샘플 뒤의 종결 바이트와 4-byte 정렬도 다음 헤더 및 마지막 노래 헤더와 일치한다. 비교 자료는 [m4a 구조 선언](https://github.com/pret/pokeemerald/blob/master/include/gba/m4a_internal.h)이다.

`tools/classify_text_candidates.py`의 결과에서 349개 후보는 이 검색에 잡힌 참조가 모두 PCM 샘플 내부였다. 그중 18개는 기존 한국어 바이트를 문장 중간부터 디코딩해 오류처럼 보이던 경우다. 실제 기술 표에 참조가 있는 나머지 디코딩 실패 2개는 기존 기술명 18개 보완에 포함되어 있다.

음성의 우연한 바이트를 참조로 인정하지 않는 것이며, 해당 주소에 실제 문자열이 존재할 가능성 자체를 지우지 않는다. 다른 정상 호출자가 발견되면 그 근거로 별도 채택한다. 7914개 남은 후보도 확정 문자열·미번역 수가 아니다.

`source/nontext_profile.json`은 5377320 bytes의 PCM 은행을 보호한다. 현재 일본판·v1.1·v1.1a에서 해당 바이트가 동일하며, 누적 빌드는 이 영역의 변경을 거부한다. 범위 밖의 데이터까지 모두 분류했다는 뜻은 아니다.

## 현재 채택한 소형 표시

910개 이름 필드, 팀 칭호/보너스 54개 슬롯, 선택 UI 72개 리터럴/표 필드를 채택했다. 54개는 원래 58개 팀 규칙과 조회 코드에 근거한다. 칭호 23번 및 보너스 9/11번은 이 규칙에서 선택되지 않으므로 슬롯은 보존·번역하되 정상 게임의 도달을 주장하지 않는다.

기존 문장 및 그래픽, 중복 이름 표, 디버그 화면, 전체 호출 경로는 별도 분류·검수 중이다. 채택 수의 증가를 100% 번역의 근거로 사용하지 않는다.

## 내부 전투 편집 메뉴의 중복 이름 표

추가 조사(2026-09-09): 7BFD78..7C00C8의 212개 포인터와 뒤의 0 종료값은 내부 전투 편집 메뉴의 몬스터 선택 목록이다. C6A8→C722→4A70의 원래 NULL 종료 목록 소비자를 확인했다. 선택 ID는 실제 몬스터 레코드 1021AC + index×56의 HP 조회에도 사용된다. 일부 내부 별칭과 오래된 오자가 있어 실제 전투용 이름 표와 문자열이 모두 같지는 않다.

보통의 Select 전투 메뉴는 17668에서 좌우 입력을 처리한 후 선택값을 0..3으로 제한한다. 176F0은 7C1D08의 행동 포인터를 읽으며, 내부 편집기를 여는 17AC0→C5DC→C550/C6A8은 다섯 번째 항목(+10, index 4)에 있다. `verify_internal_battle_menu.py`에서 정상 4개 값과 범위 밖 경계값, A/B/좌/우 조합 128개 및 실제 분기 64회를 실행해 내부 항목으로 갈 수 없음을 확인했다. 소리/커서 애니메이션만 분리 검사에서 대체했다.

따라서 이 212개 중복 이름은 해당 보통 전투 메뉴 경로의 미번역 집계에서 제외하고 원본을 보존한다. 치트·RAM 변조·모든 숨은 코드나 게임 전체의 모든 참조가 없다는 포괄적 증명은 아니다. 근거 바이트는 `source/internal_battle_menu_profile.json`에 고정했다.


## dev22 잔여 언어 후보 재조사

이미 구조가 확정된 5208개 대사 출력 레코드의 현재 문자열에서 일본어 가나/한자 범위 검색 결과는 0개였다. 문맥·오역·줄바꿈 검수 완료를 뜻하지 않는다. 기존 포인터 후보에서 PCM 내부 참조와 이미 분류한 212개 내부 몬스터 목록 참조를 제외한 뒤, 아직 같은 주소를 가리키는 곳을 검사하면 일본어 문자 후보는 275개다. 이 역시 검증된 미번역 개수가 아니다. 추가 내부 메뉴/지도 편집기, 키보드의 보존 원본, 문자열 중간을 가리키는 그래픽 데이터, 저장 장소 표와 의상 생성 문구 등이 섞여 있다. 실제 호출별 추가 판별 대상으로 유지한다.

## dev25 추가 소비자와 비활성 분기

dev23..25에서 이 후보 중 의상 제작/능력치 7개, 저장 장소 44개, 음악 제목 12개와 특수 필드 이름 1개의 실제 참조 필드를 확인해 번역했다. 같은 주소를 계속 가리키는 언어 후보는 231개로 줄었다. 이 수는 중복 문자열이 합쳐진 검색 결과이며 번역한 필드 수나 전체 게임 미번역 수와 같지 않다.

추가로 C550 내부 편집기 메뉴의 14개 제목/행동 쌍(1127A8), C6A8→C5FC가 사용하는 8개 작품 분류(7BFD10), 그 아래 7개 NULL 종료 표의 인물 별칭 93개를 확인했다. 앞서 정상 전투 메뉴에서 선택할 수 없음을 검사한 다섯 번째 행동이 이 편집기의 진입점이다. 실제 목록 복사와 작품/인물 ID 반환·취소 102개, 실제 최상위 행동 분기 14개를 검사했다. 선택기 입력과 편집 행동의 최종 호출만 시험용으로 대체했고 해당 일본어 표/게임 상태는 바꾸지 않았다.

하드웨어 오류 안내도 구분했다. 4CC0은 4CBC의 반환값이 0일 때만 그 문구를 표시하지만, 원본 4CBC는 `movs r0,#1; bx lr`로 고정되어 있다. 초기 레지스터가 다른 5회 실행 모두 표시 경로를 건너뛴다. 따라서 문자열이 존재한다는 이유만으로 일본판·v1.1의 실제 하드웨어 오류가 발생한다고 주장하거나 이 문구/검사 코드를 바꾸지 않는다.

이 근거는 source/auxiliary_exclusion_profile.json 및 tools/verify_auxiliary_exclusions.py, dev25-verified의 auxiliary-exclusion-verification.json에 남겼다. 이미 확인한 보통 실행 경로에 대한 판별이며 치트·임의 메모리 변조·모든 숨은 진입점 부재의 증거는 아니다. 지도/시나리오 편집기 등 나머지 후보의 소유자 판별은 계속 남아 있다.

## dev26 실제 플레이에서 찾은 별도 정보창

인스펙트 아이의 `16A48`은 일반 소형 4bpp 경로와 다른 affine 8bpp 소비자다. 일본어 세 항목은 앞에 `12` 제어가 있어 위 231개 포인터 후보에도 없었다. `1697C`의 실제 생산 함수를 확인해 세 항목과 한글 적 이름 출력을 보완했다. 여덟 속성 ID와 수치·판정은 데이터로 보존했다. 속성 한자 기호의 한글 표시와 다른 속성 소비자는 추가 조사 대상이다. `INSPECT_EYE.md` 참조.

## dev30 추가 비텍스트·내부 문구 판별

내부 C550 메뉴의 세부 행동 C9D0/CA98도 원래 코드로 검사했다. `7C0398`의 B 버튼 조합 4개와 `7C03F4`의 작전 5개는 각각 행동 3/7의 목록이다. 버튼 기술 지정·취소 45회와 세 인물의 작전 지정·취소 19회에서 선택기의 표, 실제 인물 구조의 변경 바이트, 나머지 1536바이트 보존을 확인했다. 상호작용 선택기만 대체한 분리 CPU 검사이며, 원본 일본어 9개는 해당 내부 메뉴의 자료로 보존한다. 기존 정상 전투 메뉴의 다섯 번째 행동에 대한 접근 범위 증거와 연결하며 모든 숨은 진입점의 부재를 주장하지 않는다.

포인터처럼 보이는 `E483B4`의 `08107AB7`, `E050A0`의 `0810B704`는 배경 압축 스트림 내부였다. 원래 BFB18/B7940 → B076C → B06A4 → 3444 → 33F4가 각각 E466B8/E03EA0 은행의 0번 자원을 BIOS LZ77 VRAM 함수에 전달함을 실행으로 확인했다. 목적지는 06000000이다. 독립 압축 해제 결과 33867/33873바이트와 입력의 정확한 소비 범위를 검사했으며, 해당 4바이트는 리터럴·압축 플래그·역참조의 일부다. 일본판/v1.1/dev30에서 압축·해제 바이트와 경로가 모두 같다.

이는 해당 두 값이 문자열 참조가 아니라는 판별이다. 값이 우연히 가리키는 주소에 다른 실제 문자열 소비자가 없다는 뜻은 아니다. `source/graphics_candidate_edge_profile.json`, `tools/verify_graphics_candidate_edges.py` 및 `qa/results/dev30-additional-classification`에 범위와 해시를 보존한다. dev30 빌드 후 추가 검사로, 기존 동결 빌드 기록과 검토 ZIP은 바꾸지 않았다. 다음 누적 빌드부터 이 압축 그림 검사도 실행한다.


## dev36 현재 대사 재검색 (2026-09-13)

최종 dev36 ROM의 확정 VM 대사 5208개를 현재 포인터와 한국어 인코딩으로 다시 읽었다. 디코딩 오류 0개, 일본어 가나·한자 글자 검출 0개다. 일본어 Unicode 블록 전체로 넓게 검색하면 한국어 대사 속 ‘삐ー’ 같은 장음 부호 및 가운뎃점 ‘・’가 든 32개 레코드가 잡힌다. 이를 미번역 일본어 문장 32개로 집계하지 않는다. 근거는 `qa/results/recipe-layout-dev36/dialogue-language-scan-dev36.json`.

이 수치는 이미 구조가 확인된 대사만 포함한다. 미확정 시스템/튜토리얼/그래픽 글자, 후반·분기·엔딩의 전수 표시와 의미 검수는 남아 있다. 현재 정상 플레이에서 발견한 미번역 일본어 문장을 새로 확정한 것은 없지만, 전체 게임에 미번역이 없거나 100% 완료됐다는 결론은 낼 수 없다. 과거 231개 등 바이트 후보를 현재 미번역 수로 재사용하지 않는다.
