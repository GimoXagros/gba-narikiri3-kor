# dev32 소형 글자 교체 경계 수정

2026-09-12. v1.1a 개발판의 글자 저장 공간 검사에서 발견한 오류다. 실제 본편에서 124종류가 동시에 표시된 장면을 발견했다는 뜻은 아니다.

dev31은 124개 칸이 모두 사용 중일 때 한 글자를 새 글자로 바꾸는 경우에도 곧 덮어쓸 목적지의 옛 글자까지 보호했다. 옛 글자를 다른 칸에서 쓰지 않으면 그 공간을 재사용할 수 있는데도 `?`를 출력했다. 원래 두 Thumb 출력기를 실행한 구성 검사에서 이러한 8건이 실패했다.

수정은 할당기에 정확한 목적지 셀 주소를 전달하고 참조 조사에서 그 셀 하나만 제외한다. 같은 타일을 참조하는 다른 셀은 계속 보호한다. 창 출력은 기존 줄바꿈·스크롤 처리 후의 좌표로 목적지를 계산하고 별도 출력은 원래 셀 포인터를 전달한다. 타일 그림 비교, 가나 복구, 탁점, 간격, 다른 타일 범위와 영구 RAM 사용량은 바꾸지 않는다.

두 배경 × 두 출력기 × 한글/가나 교체 × 옛 글자 단독/공유 사용의 16건을 검사한다. 새 한글 픽셀은 달무리 원본 비트, 가나는 원래 atlas와 비교한다. 다른 123글자와 공유된 옛 글자도 보존해야 한다. dev32는 16건 모두 통과한다. 옛 글자가 다른 셀에도 남아 있어 실제로 공간이 부족한 8건은 기존 보호 동작을 유지한다. `tools/verify_cache_replacement.py`를 누적 빌드와 꾸러미 필수 조건에 추가했다. 실패한 dev31 보고서도 `qa/results/dev32-cache-replacement/before-dev31.json`에 보존한다.

현재 ROM은 `output/v1.1a-dev32-verified-01/ND3_B3TJ_K_v1.1a.gba`, SHA-256 `1051612d3027c315596e28a5eb78451287bde5926e57d45268537c90c29b56ca`다.

- 두 후크 합계 752바이트, SHA-256 `95430c70456fdc632ed07ae9202aa3c6ddda116745087d5e31ebb5835e3b2b85`.
- dev31과 586바이트 차이. 확장 후크 구간과 별도 출력 진입 주소 이외 모든 바이트가 동일하다. 번역 문자열과 행동 데이터는 변경하지 않았다.
- 정확한 새 ROM의 27개 분리 CPU 검사 통과. 대사 5208개 × 6조건의 전수 픽셀 검사도 포함한다.
- 두 PC 코어 새 게임·첫 저장·새 프로세스 재로드와 8개 화면 직접 관찰. 저장/주 메뉴는 dev31과 이미지 동일하고 아이템/설명 화면의 차이는 손 커서 애니메이션 95픽셀에만 있다.
- 첫 문/보물상자 경로와 새 중단 저장 재로드도 확인했다. `docs/FIRST_CHEST_ROUTE.md` 참조.
- 이름 후보판 경로를 각 35879프레임 측정해 최대 102개 참조를 기록했다. 최대 시점의 두 화면을 직접 확인했다. 전체 화면 모집단이나 프레임 내부의 최대치 증거는 아니다.

실제로 125종류를 동시에 유지해야 하는 상태의 공간 부족은 해결된 것으로 처리하지 않는다. 모든 화면의 최대 집합과 글꼴 재로딩 수명 검증은 남아 있다. 기존 재로더 `08002128`을 향한 코드 구간의 정렬된 직접 BL 후보 24곳을 조사했지만, 간접 호출·다른 로더·모든 복귀 경로까지 완성된 모집단은 아니다. 이번 수정은 재현된 불필요한 공간 부족 하나를 해결한 것이다.
