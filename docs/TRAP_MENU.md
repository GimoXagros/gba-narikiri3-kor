# 함정 설치 메뉴 5개 항목

dev31은 `DD24A4`의 NULL 종료 포인터 표에 있는 트라바사미·폭탄·독 덫·깜짝 폭탄·종료 항목을 `덫 / 폭탄 / 독 덫 / 깜짝 폭탄 / 종료`로 표시한다. 실제 이야기 코드 `B9060 → B9470`, `BDD42 → BDF34`가 `AE024 → AE1D0`으로 이 메뉴를 부른다. 내부 편집 메뉴로 분류했던 문구와 별개인 정상 시나리오의 표시 대상이다. 사용자 제공 공식 가이드에도 임무 시작 전 네 종류의 함정을 설치하는 진행과 이름·효과 표가 있다.

`AE1D0`은 원래 8칸 폭, 5개 항목, B 취소 금지로 `AED8C`를 호출한다. 일반 목록 생성기 `402C`가 0 포인터까지 세고, `4488 → 1DA8`이 각 이름을 그린다. 목록 ID 0..3은 그대로 설치 함수 `AE050`에 전달되며, ID 4는 -1로 바뀌어 설치를 끝낸다. 실패한 설치는 남은 개수를 줄이지 않는다.

기존 UI 재삽입 경로에 `trap-menu-00..04`를 추가했다. 일본어 가나 표기 전환용 `%h`는 한글에 필요하지 않아 기존 UI 선택 규칙에 따라 제거했으며, 숫자·변수·버튼 명령은 이 다섯 이름에 없다. 선택한 이름은 최대 5칸으로 원래 8칸 안에 든다. dev30과 비교한 변경은 다섯 포인터 `DD24A4..DD24B7`와 UI 문자열 `1060400..1060424`의 49바이트뿐이다. 원래 함정 효과·배치·개수·이야기 코드와 기존 문자열은 모두 그대로다.

`verify_trap_menu.py`는 원래 창 초기화·목록 할당·다섯 이름 출력을 두 모드에서 실행한다. 문자 위치와 포맷 임시 공간을 검사하고, 전체 32768바이트 타일 맵 픽셀을 원본 빈 창과 독립 한글 비트맵으로 조합한 참조와 비교한다. 원래 커서 이동 및 양 끝 순환 24회, 실제 설치 개수·실패·종료 분기 4개 사례도 통과했다. 개수 검사에서는 상호작용 선택기와 배치 행동만 시험용 반환값으로 대체하며 실제 저장에 이 상태를 넣지 않는다. 두 출력 이미지를 직접 확인했다.

첫 검사 실패는 검증 코드가 원래 목록 할당 주소를 `03002350`으로 잘못 적은 데서 발생했다. 원본 `4008`의 리터럴은 `03002A50`이며, 검사만 수정한 뒤 같은 ROM에서 통과했다. 게임 오류로 분류하지 않는다. 정상 진행으로 후반의 두 함정 설치 시나리오에 도달하는 화면 검수는 남아 있다.
